# 複数ZIPダウンロードツール（multi-zip-downloader.html）

Web経由で配布しているZIPファイルが、Chromeブラウザから正常にダウンロードできるかを、複数の配布先についてまとめて確認するためのツールです。
URLを1件ずつコピー＆ペーストする作業をなくし、指定したURLを **新しいタブを開かずに順番にダウンロード** します。

---

## 特徴

- HTMLファイル1つで動作します（インストール・管理者権限・拡張機能は不要）
- タブを増やさず、非表示のiframeで1件ずつダウンロードするので、スペックの低い環境でも軽く動きます
- 1件ごとの結果、保存名の予測、時刻を一覧で表示します
- 結果をTSV形式でコピーでき、Excelの試験記録にそのまま貼り付けられます

---

## 動作環境

| 項目 | 内容 |
|------|------|
| ブラウザ | Google Chrome（Edgeでも動作する想定） |
| 実行方法 | ローカルに保存したHTMLファイルをブラウザで開く |
| 対象URL | `http://` または `https://` のURL |

> **注意**：このHTMLをhttpsのWebサーバ上に置いて開くと、httpのダウンロードがブラウザにブロックされます。必ずローカルファイルとして開いてください。

---

## 事前準備

1. **保存場所の確認をオフにする**
   Chromeの「設定 → ダウンロード → ダウンロード前に各ファイルの保存場所を確認する」を **オフ** にします。
   オンのままだと、1件ごとに保存ダイアログが出て処理が止まります。
2. **ダウンロード先フォルダを空にする**
   同じ名前のファイルが残っていると、保存名の予測（`test (n).zip` の番号）がずれます。
3. **ツールを開く**
   `multi-zip-downloader.html` をダブルクリックし、Chromeで開きます。

## 使い方

### 1. 対象を入力する

入力方法は2つあり、タブで切り替えます。

#### 「IP + xxxxxx」タブ

| 入力項目 | 内容 | 例 |
|----------|------|----|
| IPアドレス | 配布サーバのIPアドレス（ポート付きも可） | `192.168.10.20`、`192.168.10.20:8080` |
| ファイル名 | 配布するファイル名 | `test.zip`（初期値） |
| xxxxxx | URLのディレクトリ部分。1行に1つ | `xxxxxx-001` |

次の形式のURLを自動で作ります。

```
http://<IPアドレス>/<xxxxxx>/<ファイル名>
```

#### 「URL直接入力」タブ

URLを1行に1つずつ貼り付けます。`http://` を省略した場合は、自動で付け足します。

```
http://192.168.10.20/xxxxxx-001/test.zip
http://192.168.10.20/xxxxxx-002/test.zip
```

### 2. オプションを設定する

| オプション | 内容 |
|------------|------|
| ダウンロード間隔（秒） | 次のファイルに進むまでの待ち時間です（初期値3秒）。詳しくは「ダウンロード間隔の決め方」を参照してください |
| キャッシュ回避 | URLの末尾に `?t=時刻` を付け、ブラウザキャッシュから取ってきたことによる誤判定を防ぎます |
| 検証モード | HTTPステータス、サイズ、ZIP形式かどうかを確認し、`xxxxxx_ファイル名` という名前で保存します。詳しくは「検証モード」を参照してください |

### 3. 実行する

| ボタン | 動作 |
|--------|------|
| URL一覧を確認 | ダウンロードせずに、対象のURL一覧だけを表示します |
| ダウンロード開始 | 上から順番にダウンロードします |
| 停止 | 実行中のダウンロードが終わった時点で止めます。残りは「中止」になります |
| 結果をコピー | 結果一覧をTSV形式でクリップボードにコピーします |

初回は、Chromeに「このサイトが複数のファイルをダウンロードしようとしています」と表示されます。**「許可」** を押してください。

### 4. 結果を確認する

| 結果 | 意味 |
|------|------|
| ダウンロード要求済 | ブラウザがダウンロードを始めました |
| 要確認 | ダウンロードではなくページが表示されました（404や接続エラーなどの可能性があります） |
| OK | （検証モードのみ）HTTP 200で、ZIP形式であることを確認しました |
| NG | （検証モードのみ）HTTPエラー、またはZIP形式ではありませんでした |
| 中止 | 停止ボタンで実行されなかった分です |

画面下部のサマリーで、全件数、OK・要求済の件数、要確認の件数、NGの件数を確認できます。

> **重要**：通常モードの「ダウンロード要求済」は、ダウンロードが **始まったこと** までしか判定できません（ブラウザの制約です）。
> ダウンロードが最後まで終わったかは、`chrome://downloads` で確認してください。

## 保存名（予測）について

通常モードでは、Chromeが同じ名前のファイルに自動で番号を付けます。

```
test.zip → test (1).zip → test (2).zip → …
```

ツールはこのルールに沿って、各行の保存名を予測して表示します。

- 「要確認」の行はファイルができないので、番号を数えません（`-（保存なし）` と表示します）
- ダウンロード先フォルダに同じ名前のファイルがない状態から始めることが前提です
- 同じ名前のファイルが非常に多い場合（目安として100件前後）、Chromeの番号の付け方が変わることがあります。件数が多いときは事前に試してください

予測した保存名は「結果をコピー」にも含まれるので、xxxxxxとファイル名の対応表として試験記録に残せます。

---

## ダウンロード間隔の決め方

ブラウザの制約で、通常モードではダウンロードの完了を待てません。そのため、間隔は秒数で指定します。

**目安**

```
間隔（秒） ≒ ファイルサイズ ÷ 実際に出る回線速度 × 1.5〜2
```

例：50MBのファイルを約10MB/sで取れる環境なら、5秒 × 2 = **10秒**

**決め方の手順（推奨）**

1. 1件だけ手動でダウンロードし、かかった時間を測る
2. 測った時間に余裕を加えた秒数を、ダウンロード間隔に設定する

間隔が短すぎると、前のダウンロードが終わる前に次が始まり、同時に走ります。失敗扱いにはなりませんが、遅い環境では負荷が上がります。

---

## 検証モード

`fetch` でファイルを取ってきて、内容を確認してから保存するモードです。

- HTTPステータス、ファイルサイズ、ZIPの先頭の目印（`PK`）を確認します
- 保存名を `xxxxxx_ファイル名` にします（番号付けは起きません）
- **配布サーバ側でCORS許可（`Access-Control-Allow-Origin` ヘッダ）が必要です**
  許可されていない場合は、自動で通常モードに切り替わります（「検証不可のため通常DL」と表示します）
- ファイルを一度メモリに読み込むので、大きいファイルでは負荷が上がります

---

## 制限事項

| 項目 | 内容 |
|------|------|
| 完了の判定 | 通常モードではダウンロードの完了を判定できません（始まったことのみ） |
| ファイル名の変更 | 通常モードではできません（別サーバのファイルの名前をページから変えることを、ブラウザが許可しないため） |
| フォルダ分けの保存 | できません（ページからはダウンロード先のフォルダ構成を指定できないため） |
| 「要確認」の判定 | iframeのloadイベントで判断しています。ブラウザによっては正しく判定できないことがあります |

## ZIP以外のファイルについて

ZIP以外のファイルにも使えますが、ファイルの種類によって動きが変わります。

### そのままダウンロードされるもの

`.exe` `.msi` `.7z` `.xlsx` `.docx` `.csv` など、ブラウザが画面に表示できないファイルは、ZIPと同じようにダウンロードされます。

> **注意**：`.exe` や `.msi` は、Chromeの保護機能で「一般的にダウンロードされていないファイルです」などの警告が出て、保留されることがあります。
> その場合は `chrome://downloads` で、手動で「保存」を押してください。

### ダウンロードされず、表示されて終わるもの

`.txt` `.pdf` `.jpg` `.png` `.html` `.json` `.xml` など、ブラウザが表示できるファイルは、非表示のiframeの中に表示されて終わります。**ファイルは保存されず**、結果は「要確認」になります。

配布サーバが次のどちらかの形でレスポンスを返す設定になっていれば、ダウンロードされます。

- `Content-Disposition: attachment` ヘッダを付ける
- `Content-Type: application/octet-stream` で返す

**事前の確認方法**：対象のURLをChromeのアドレスバーに直接入力してください。画面に表示された場合は、このツールでもダウンロードされません。

### 検証モードでの扱い

検証モードは、ファイルの先頭がZIPの目印（`PK`）かどうかを確認します。そのため、ZIP以外のファイルは **「NG：ZIP形式ではない」** と判定されます。ZIP以外のファイルには、通常モードを使ってください。
